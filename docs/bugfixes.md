# Bug 修复记录

> 修复版本：v1.1  
> 涉及模块：`astar.py`、`robot/`、`entities/`、`simulation/`、`ui/`、`main.py`

所有修复均有对应回归测试，最终 61/61 测试通过。

## 功能性 Bug

### A* 路径规划

#### BUG-02：障碍物类型判断重复
- **现象**：A* 在判断障碍物时对 `dirt.plusDirt` 做了两次相同的 `isinstance` 判断，导致基础垃圾 `Dirt` 实际上不被识别为障碍物
- **影响**：机器人穿过基础垃圾寻路，障碍物判断逻辑不完整
- **修复**：合并为 `isinstance(obj, (dirt.plusDirt, dirt.Dirt))`
- **位置**：`astar.py` → `AStar` 障碍判断逻辑

#### BUG-03：A* 路径跟随代码被完全注释
- **现象**：机器人计算了路径但从不沿路径移动，A* 寻路形同虚设
- **影响**：所有涉及 A* 导航的行为（如充电）实际上根本没有生效
- **修复**：恢复路径跟随逻辑
- **位置**：`robot/motion.py` → 路径跟随分支

#### BUG-09：所有垃圾类型均被视为障碍物
- **现象**：`debris`（大块障碍）、`dust/crumb/paper/liquid/hair`（可通过垃圾）一律被标记为不可通行，导致地图中垃圾较多时几乎无法寻路
- **影响**：寻路成功率从 < 90% 降至实际场景中接近失败
- **修复**：只有 `debris` 类型标记为不可通行，其余垃圾类型可穿越
- **位置**：`astar.py` → 障碍物分类

#### BUG-10：起点/终点在障碍物上时寻路必定失败
- **现象**：机器人站在垃圾上时，A* 将起点标记为障碍，导致寻路直接返回 `None`
- **影响**：低电量机器人若站在垃圾上，永远无法规划路径去充电
- **修复**：寻路前清除起点和终点的障碍标记
- **位置**：`astar.py` → `find_path()`

#### BUG-22：路径点越过画布边界
- **现象**：当终点坐标为画布右下角（如 1000, 1000）时，像素坐标映射结果为 (1010, 1010)，超出画布
- **影响**：路径最后几段会让机器人向画布外移动
- **修复**：在 `_get_pixel_pos()` 中对返回坐标做边界钳制
- **位置**：`astar.py` → `_get_pixel_pos()`

#### BUG-24：首次寻路失败后不会重试
- **现象**：低电量机器人第一次寻路失败后，`path_calculated` 被置为 `True`、`path` 为空，之后即使环境恢复（如障碍移除）也不再重新调用 A*
- **影响**：机器人在障碍短暂封路后会永久停滞耗电
- **修复**：调整规划条件：若仍未到达目标充电站附近且当前路径为空，允许重新规划
- **位置**：`robot/brain.py` → 低电量规划分支

### 充电系统

#### BUG-05：充电模式提前退出（初版）
- **现象**：机器人电量 < 600 时触发充电导航，但充电退出条件也是 `>= 600`，导致机器人充到 600 就退出，无法充满
- **影响**：机器人反复在半充电状态进出充电模式，能量管理失效
- **修复**：保留"充满电才退出"规则，提取 `reset_charging_state()` 统一清理充电相关状态
- **位置**：`robot/brain.py` → 充电退出判断

#### BUG-12：充电模式再次提前退出（二次修复）
- **现象**：充电时每帧电量先 `-1` 再 `+10`，若充到 600 以上就被错误清出充电状态，导致永远充不满
- **影响**：机器人进入充电站后在 600～999 电量区间反复跳出
- **修复**：仅在充满电或显式重置目标时退出充电模式，充电时同步钳制上限为 1000
- **位置**：`robot/brain.py` → 充电状态管理

#### BUG-13：删除充电站后机器人持有悬挂引用
- **现象**：充电站被删除后，正在以该站为目标的机器人仍保留 `target_charger`、`path`、`path_calculated` 和低电量状态
- **影响**：机器人引用已删除对象，行为异常甚至崩溃
- **修复**：`remove_charger()` 增加 `agents` 参数，删除充电站时同步重置所有指向该站的机器人状态
- **位置**：`simulation/factory.py` → `remove_charger()`

#### BUG-14：删除正在充电的机器人不释放充电站占用
- **现象**：被删除的机器人若正在充电，`Charger.is_charging` 和 `charging_bot` 保持旧值，其他机器人认为该站永久被占用
- **影响**：充电站被锁死，其他机器人无法使用
- **修复**：`remove_bot()` 增加 `chargers` 参数，删除机器人前遍历充电站并释放占用锁
- **位置**：`simulation/factory.py` → `remove_bot()`

#### BUG-18：等待被占用充电站时耗电过快
- **现象**：机器人已到达充电站附近但该站被占用，`path` 为空，等待时按正常速率每帧掉 1 点电
- **影响**：机器人在近距离等待期间持续掉电，可能在等待中耗尽电量
- **修复**：等待判定改为基于"处于充电模式 + 低电量 + 目标站被占用"，不再依赖 `path` 是否为空
- **位置**：`robot/brain.py` → 等待充电站逻辑

#### BUG-23：远距离时也因充电站被占用而原地等待
- **现象**：低电量机器人只要目标站 `is_charging` 就进入等待，即使自身还在远处，导致机器人在半路停住
- **影响**：机器人不能趋近充电站，能量在等待中耗尽
- **修复**：新增 `near_target_charger` 判定，仅在进入充电站检测半径（`distance < 80`）后才等待，远距离继续路径跟随
- **位置**：`robot/brain.py` → 充电导航分支

### 机器人行为

#### BUG-04：`overlap_threshold` 硬编码
- **现象**：`overlap_threshold` 定义为 20000，但实际判断处硬编码为 50000，两者不一致
- **影响**：重叠检测阈值无法通过修改属性生效
- **修复**：判断处改为使用 `self.overlap_threshold`
- **位置**：`robot/brain.py` → 重叠分离判断

#### BUG-06：`debris_count` 传参错误
- **现象**：主循环递归时传入 `current_debris` 而非 `debris_count`，导致垃圾计数追踪失效
- **影响**：垃圾收集统计不准确
- **修复**：改为传入 `debris_count`
- **位置**：`simulation/engine.py` → 主循环

#### BUG-16：灯光信号误触发机器人避让
- **现象**：`Bot` 将灯光传感与机器人传感合并后传入 `Brain`，`Brain` 用这组值做避让和重叠判断，导致附近只有灯、没有其他机器人时也误进入避让状态
- **影响**：机器人在有灯光但无其他机器人时异常偏转，全速直行能力受损
- **修复**：拆分机器人 proximity 传感与灯光传感，避让/重叠逻辑仅使用机器人传感值
- **位置**：`robot/sensing.py`、`robot/brain.py`

#### BUG-17：零电量后机器人仍继续移动
- **现象**：`battery <= 0` 时只做了下限钳制，没有中断路径跟随和 `move()`，机器人没电后仍继续前进
- **影响**：机器人在无法充电时理论上应停止运动，但实际仍持续消耗逻辑资源并产生视觉噪声
- **修复**：充电检测之后增加"零电量停机"分支，本帧若未在充电站补电则将轮速清零并直接返回
- **位置**：`robot/brain.py` → 零电量分支

#### BUG-25：直线运动忽略时间步长 `dt`
- **现象**：`move()` 在 `sl == sr` 直线分支中位移只乘轮速，未乘 `dt`，调高仿真速度时转弯加快但直线速度不变
- **影响**：不同速度档位下机器人运动学行为不一致
- **修复**：直线分支改为 `speed * dt * cos(theta)` / `speed * dt * sin(theta)`
- **位置**：`robot/motion.py` → `move()` 直线分支

#### BUG-26：移动后越界坐标延迟一帧才修正
- **现象**：边界 wrap 只在 `Brain.thinkAndAct()` 中处理，`move()` 本身不做 wrap，机器人越界后以错误坐标渲染一整帧
- **影响**：机器人穿越边界时会短暂显示在画布外
- **修复**：在 `move()` 末尾增加即时边界 wrap，坐标更新后立即修正
- **位置**：`robot/motion.py` → `move()` 末尾

### 实体与仿真

#### BUG-07：充电站充电状态视觉不刷新
- **现象**：充电状态变化后没有代码触发充电站重新 `draw()`，视觉反馈滞后
- **影响**：充电状态指示灯不实时更新
- **修复**：主循环中每帧刷新充电站绘制
- **位置**：`simulation/engine.py` → 主循环

#### BUG-15：基础 `Dirt` 类型无法被收集
- **现象**：`collectDirt()` 只处理 `plusDirt`，而以 `dirt_plus=False` 模式创建的基础 `Dirt` 对象即使与机器人重合也不会被移除或计数
- **影响**：普通垃圾模式下机器人永远无法清洁，计数始终为 0
- **修复**：扩展 `collectDirt()` 同时支持 `Dirt` 和 `plusDirt`，基础垃圾走单次清理
- **位置**：`robot/cleaning.py` → `collectDirt()`

#### BUG-27：猫移动忽略时间步长 `dt`
- **现象**：`Cat.update()` 接收了 `dt` 参数但实际位移只乘 `speed`，未乘 `dt`，调节仿真速度时猫的速度不随之缩放
- **影响**：猫与机器人的速度在不同仿真速度档下不一致，影响避猫行为的真实感
- **修复**：猫的位移改为 `speed * dt`
- **位置**：`entities/cat.py` → `update()`

### 启动与 UI

#### BUG-01：`initialise()` 和 `buttonClicked()` 重复定义
- **现象**：`initialise()` 和 `buttonClicked()` 在文件中各定义了两次，Python 后定义覆盖前一个，导致第一个版本中的 `resizable(False, False)` 设置被丢弃
- **影响**：窗口大小可以被拖动调整，布局错乱
- **修复**：删除重复定义，在保留版本中补回 `resizable` 设置
- **位置**：`app/bootstrap.py`

#### BUG-11：`initialise()` 对 `Frame` 调用 `resizable()`
- **现象**：`initialise()` 直接调用 `parent.resizable(False, False)`，但传入的是 `tk.Frame`，`Frame` 没有该方法，程序启动时抛出 `AttributeError`
- **影响**：程序启动即崩溃
- **修复**：改为 `parent.winfo_toplevel().resizable(False, False)`
- **位置**：`app/bootstrap.py` → `initialise()`

#### BUG-19：模块被导入时触发 GUI 启动
- **现象**：文件尾部直接调用 `main()`，导致 `import` 或测试环境中也会创建 Tk 窗口
- **影响**：测试无法在无 GUI 环境下运行，测试耗时大幅增加
- **修复**：改为 `if __name__ == "__main__": main()`
- **位置**：`main.py` → 入口

#### BUG-20：重置后暂停按钮显示状态不一致
- **现象**：`reset_simulation()` 恢复 `simulation_running = True` 但不同步更新按钮文本，用户在暂停状态下重置后，仿真已运行但按钮仍显示"▶ 继续"
- **影响**：UI 状态与仿真状态不同步，用户无法判断当前状态
- **修复**：`reset_simulation()` 中显式将暂停按钮恢复为"⏸ 暂停"和对应颜色
- **位置**：`simulation/engine.py` → `reset_simulation()`

## 设计问题

### DES-01：Toroidal 边界处理重复 5 次
- **问题**：`Brain.thinkAndAct()` 中边界 wrap 逻辑重复出现 5 次，分散在各个运动分支末尾
- **修复**：重构为 if/elif 结构，末尾统一处理一次
- **位置**：`robot/brain.py` → `thinkAndAct()`

### DES-02：传感器距离计算重复 4 次
- **问题**：`senseLight`、`senseOtherBots`、`senseChargers`、`senseDebris` 各自独立实现相同的距离计算逻辑
- **修复**：提取为 `_calculate_sensor_values()` 公共方法
- **位置**：`robot/sensing.py`

### DES-03：猫跳离方向反向
- **问题**：`Cat.jump_away()` 本意是让猫跳离机器人，但向量计算方向取反，实际让猫跳向机器人
- **修复**：修正跳离向量，使其沿远离机器人的方向
- **位置**：`entities/cat.py` → `jump_away()`

### DES-04：实体文件含大段注释旧代码
- **问题**：`dirt.py`、`charger.py`、`counting.py` 中存在大量被注释的旧版代码，降低可读性
- **修复**：删除所有注释掉的旧版实现
- **位置**：上述三个文件

### DES-05：未使用的全局变量 `simulation_objects`
- **问题**：`simulation_objects` 定义后从未被引用，属于遗留死变量
- **修复**：删除
- **位置**：`simulation/state.py`

### DES-06：`update_stats()` 和 `add_random_dirt()` 为死代码
- **问题**：两个函数定义后从未被调用
- **修复**：删除
- **位置**：`simulation/stats.py`、`simulation/factory.py`

### DES-07：`== True` 冗余比较
- **问题**：`if self.currentlyTurning == True:` 是多余的布尔比较
- **修复**：简化为 `if self.currentlyTurning:`
- **位置**：`robot/brain.py`

### BUG-08：`None` 比较使用 `!=` 而非 `is not`
- **问题**：两处 `None` 比较使用了 `!=` 运算符，不符合 Python 惯用法，且在某些边界情况下行为不同
- **修复**：改为 `is not None`
- **位置**：`robot/brain.py`

### BUG-21：`move()` 使用 `np.matrix` 触发弃用警告
- **问题**：每次调用 `move()` 都产生 `PendingDeprecationWarning`，污染测试输出，且依赖过时 API
- **修复**：删除 `np.matrix` 旋转矩阵实现，改用等价的显式微分驱动运动公式；同时移除 `numpy` 导入
- **位置**：`robot/motion.py` → `move()`
